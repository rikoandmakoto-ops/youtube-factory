# ショート動画への「解説画像」追加 — 提案書（実装前のたたき台）

作成: 2026-06-27 / ステータス: **提案のみ。動画の見た目はまだ変更していない。**
次のステップ: 本提案で方向性を決めたら、**サンプルフレームを1〜2枚生成してユーザー確認 → 承認後に実装**。

---

## 1. 結論サマリ

- いまのショートは「背景＋中央のキャラ1人＋字幕」だけで、**解説画像（図解・イラスト）は一切出していない**。フル動画には約30秒ごとに図解を差し込む仕組み（`illustration_style` / `use_illustrations`）が既にあるが、ショートの描画パスはこれを通っていない。
- ショート画面の**上半分が背景しか無く空いている**。ここに「いま喋っている内容の図解」を出せば、無音スクロールでも内容が伝わり、維持率・保存率の改善が期待できる（競合のバズショートはほぼ全て図やテロップ画像を多用）。
- 両チャンネルとも**図解スタイル設定は既に定義済み**（daily-science＝教科書風カラー図解 / scp-lab＝流出文書風モノクロ図解）。つまり「フル動画用の資産をショートにも流用する」だけで、新しい画像トーンを作る必要は小さい。
- 推奨は **案B（キャラ上の図解カード）** をベースに、冒頭フックだけ図解を出さない（インパクト演出を邪魔しない）ハイブリッド。

---

## 2. 現状のショート構成（変更前）

縦 **1080 × 1920 (9:16)**。`ShortFrameRenderer`（`backend/pipeline/video_generator.py:1393` 以降）が1セリフ＝1クリップで描画。

レイヤー（下→上）:
1. **背景** … 静止画 or Pexels 収集画像を 9:16 にクロップ（`_get_bg_frame` `video_generator.py:1481`）。SCPは `short_bg_query`、フォールバックは暗色。
2. **SCPバッジ**（scp-labのみ・上部 y≈90）… タイトルからSCP番号を抽出して赤下線の黒箱で表示。
3. **キャラ1人**（中央 円アイコン・直径280px・`cx=540, cy=580`）… 話者だけ。フル動画は2人横並びだがショートは1人。
4. **字幕**（キャラの下・y≈700〜1700）… 64px、冒頭フックのみ 72〜104px の特大演出。
5. **出典クレジット**（右下・小・26px）。

```
        ┌───────────────────────────┐  y=0
        │      [SCP badge]          │  ← scp-lab のみ
        │                           │
        │    ███  ← 空きスペース     │  ★ここが丸ごと空いている
        │   （背景のみ・上半分）      │     = 図解を置く最有力ゾーン
        │                           │
        │        ( ◯ )  キャラ       │  y≈580
        │         名前               │
        │  ┌─────────────────────┐  │
        │  │  字幕テキスト          │  │  y≈700-1700
        │  │  （2〜3行）            │  │
        │  └─────────────────────┘  │
        │                    出典→   │  y≈1860
        └───────────────────────────┘  y=1920
```

**重要:** 冒頭3秒は「特大フック演出（暗転＋パンチイン）」が入る（`short_overlay_style.opening`、`video_generator.py:1661`）。ここに図解を被せるとインパクトが死ぬので、図解は**フック明け以降**に出すのが前提。

## 3. なぜ今これをやるか（狙い）

- ショートは音声オフで流し見されるため、**画面に「内容を示す絵」がある=スクロールを止める**フックになる。
- daily-science は「お腹の音」「42度の風呂」など**図解が刺さる題材**が中心。scp-lab も「収容違反現場」「オブジェクトの姿」を示唆する図が相性良い。
- フル動画用の図解生成（DALL-E gpt-image-1）とスタイル設定が**既にある**ため、追加コストは「ショート描画パスへの差し込み」と「1本あたり画像1〜2枚の生成費」のみ。

---

## 4. レイアウト案（3つ）

### 案A: 背景置き換え型（全面図解）
図解を背景レイヤーごと差し替え、上に半透明グラデ＋字幕を載せる。
- ⭕ インパクト大・情報量最大。競合のバズショートに最も近い。
- ❌ キャラの存在感が薄れる。図解の出来に動画品質が直結。毎カット別画像だと生成費・時間が増える。

### 案B: 図解カード型（キャラの上に差し込む）★推奨
空いている上半分（y≈250〜650）に図解を角丸カードで配置。キャラはやや下げる or そのまま。フル動画の図解描画（`_render_illust_frame` `video_generator.py:1043`）をショート寸法に縮めて流用。
- ⭕ 既存レイアウト・キャラを維持したまま情報追加。トーンの作り込みが既存資産で済む。フック演出と両立（フック中は非表示）。
- ❌ 図解が小さめ（横≈900px）。1ショートに図解は1〜2枚が現実的。

### 案C: タイミング・スライドイン型
セリフの切れ目（ビート）に合わせて図解を横からスライドイン／フェードして数秒だけ表示。
- ⭕ 動きが出てリテンション最強クラス。
- ❌ 実装コスト最大（タイミング制御・アニメ追加）。まずBで土台を作ってからの発展形が妥当。

---

## 5. 推奨プラン（ハイブリッドB）

1. **冒頭フック（〜3秒）**: 図解なし（現状の特大演出を維持）。
2. **本編**: 1ショートにつき図解 **1〜2枚**を案Bのカードで表示。題材は「そのセリフ群の要点」（フル動画の `plan_illustrations` `video_generator.py:894` と同じ要約ロジックを流用）。
3. **トーン**: チャンネル既存の `illustration_style` をそのまま使用（daily-science=教科書風カラー / scp-lab=流出文書風モノクロ）。ショート用に `format` を `portrait` 寄りにするか要検討。
4. **生成モード**: daily-science は `generate`（DALL-E）、scp-lab は `collect`（Pexels）が既定。ショートでもこれを踏襲。
