> 本レポートは (1) 台本テキストの保存状況、(2) 登録者増に寄与した動画の分析、(3) 至上戦略に沿ったパイプライン・テーマ選定の改善提案 をまとめる。

## 0. 3行サマリ（最重要）

1. **台本はテキストで保存されている。** `data/scenarios/<channel>/*.json`（最新）と `data/scenarios/<channel>/archive/*_scenario.md`（アーカイブMarkdown）に、サムネ案・ショート台本・フル台本（セクション別）まで全文残っている。消失リスクは低い。
2. **「登録者が増えた動画」は現状データからは特定不能。** 両チャンネルの YouTube OAuth リフレッシュトークンが**失効/取り消し済み**（`invalid_grant`）で、6/27以降の分析が全て空振り。`video_metrics` 617行はすべて再生≒0・登録者増0、`channel_metrics` は0行。**登録者を至上戦略に置くなら、まず“登録者を測れる状態”に戻すことが最優先タスク。**
3. **競合の実データ（外部・生きているデータ）が示す勝ち筋は、現行パイプラインとほぼ真逆。** 登録者を稼ぐ同ジャンル上位チャンネルは「長尺（10〜100分）の深掘り」または「高品質アニメ」で、**低頻度・高品質**。現行は「テキストカードのショートを1日1〜2本量産」で、登録導線（CTA）も内部評価で最下位。

## 1. 台本テキストの保存状況（タスク1）

### 結論: 保存されている（二重に残る設計）

| 種別 | 保存先 | 形式 | 中身 |
|---|---|---|---|
| 最新版 | `data/scenarios/<channel>/<タイトル>.json` | JSON | 構造化された台本一式 |
| アーカイブ | `data/scenarios/<channel>/archive/<prefix>_<timestamp>_scenario.md` | Markdown | frontmatter + 全台本（人間可読） |
| アーカイブ索引 | `data/scenarios/<channel>/archive/_index.json` | JSON | 生成履歴のインデックス |

`ds_short_*` / `daily-science_short_*` はショート、`daily-science_<timestamp>_scenario.md` は長尺。直近30本のうち **ショート18 / 長尺12** が生成されている。

### アーカイブMarkdownに含まれる要素（1ファイルで完結）

```
---
title / video_title / channel_id / prefix / style
generated_at / prompt_hash / theme_title / theme_angle
generated_by: claude / selected_by: blind_eval
---
# タイトル
**公開タイトル案** / **生成モデル**（Claude Sonnet 4 など）
## サムネ情報   (hook_lines / subtitle / tagline を JSON で保持)
## ショートシナリオ   (理子・真の掛け合い＝実際に使うショート台本)
## フルシナリオ（セクション別）
   ### フック / 導入 / 展開1..N / まとめ
```

### パイプライン上の生成→消費フロー
- **生成**: `pipeline/` のシナリオ生成（`generated_by: claude`）。複数モデルで生成し `blind_eval`（model-compete）で最良案を選抜（`analytics.db: model_scenario_records` 259件, `scenario_evaluations` 124件が証跡）。
- **保存**: 上記 JSON + アーカイブMD に書き出し。
- **消費**: レンダリング工程が台本を読み込み、TTS → 立ち絵・背景・字幕合成 → 動画化 → アップロード。
- **評価**: `scenario_evaluator` が台本を採点（hook/具体性/pacing/CTA/wording）して `scenario_evaluations` に蓄積。

**→ 台本の“消失”は起きていない。むしろ資産として溜まっているので、後述する「登録者が増えた台本の逆算学習」に使える状態。**（ただし現状は成果指標が欠測なので学習に使えていない。）

## 2. 登録者に寄与した動画の分析（タスク2）

### 2-1. 最重要の発見: 成果測定が“全断”している

調査で判明した事実:

- `data/reports/*/report.md` は 6/27〜7/3 まで毎日生成されているが、**全チャンネル・全動画で「登録者: —」「再生 0」**。判定は毎回「登録者ソースが取得できないため判断保留」。
- 一次データ `data/analytics/analytics.db`:
  - `video_metrics`: **617行あるが 合計再生4・最大再生2・登録者増0・いいね2**。6/27以降は毎日100本スナップショットを取っているが全て0。
  - `channel_metrics`（登録者増減の本命テーブル）: **0行**。
- レポートJSONの `sync` セクションにエラー: `"OAuth 未連携または googleapiclient 未導入"`。
- 直接検証の結果、`googleapiclient` は導入済み・トークンはDBに存在・JWT_SECRETでの復号も成功。しかし **リフレッシュ時に両チャンネルとも失敗**:

  ```
  daily-science: RefreshError invalid_grant: Token has been expired or revoked.
  scp-lab:       RefreshError invalid_grant: Token has been expired or revoked.
  ```

**結論: 両チャンネルの YouTube OAuth が失効しており、YouTube Analytics/Data API が一切叩けていない。** そのため「どの動画が登録者を獲得したか」は**現データからは物理的に特定できない**。

> メモリ上の既知事象（`daily-science` OAuth失効・UI再認証が redirect_uri_mismatch でブロック）が、今や `scp-lab` にも波及している。以前 scp-lab は生きていたため、これは新規劣化。

#### これが至上戦略に対して持つ意味
「登録者数の増加を至上戦略とする」なら、**登録者数を毎日計測できることが大前提**。現状はKPIが盲目状態で、どんな施策も効果測定できない。**改善提案の No.1 はここの復旧**（§3-A）。

## 3. 至上戦略に基づく改善提案

優先度順。**A（測定復旧）は他すべての前提**。

### A. 【P0・最優先】登録者を“測れる”状態に戻す
現状KPIが盲目。以下を復旧しないと、以降の施策の効果は一切判定できない。

1. **両チャンネルの YouTube OAuth 再認証**（`invalid_grant` 解消）。
   - `daily-science` は UI 再認証が `redirect_uri_mismatch` でブロック（既知）。→ **Google Cloud Console の OAuth クライアントの「承認済みリダイレクトURI」を、バックエンドの実 `redirect_uri` と一致させる**のが先決（`oauth_state.redirect_uri` に実値あり）。
   - `scp-lab` も今回新たに失効を確認。同様に再認証が必要。
2. **`channel_metrics` への登録者スナップショットを日次で確実に記録**（`fetch_channel_overview` が通れば `subscribers_gained/lost` が入る）。
3. **トークン失効の監視・自動アラート**を追加。`_token_refresh_check.py` を launchd 日次で回し、`invalid_grant` を検知したら通知（メール/Push）。失効は繰り返し起きているので“検知の自動化”が要る。
4. 復旧後、**登録者あたりの貢献度指標 `subs_gained / views`（1000再生あたり登録）を動画別に集計**し、レポートの主軸KPIに昇格（再生数ではなく登録転換率で動画を評価）。

### B. 【P1】フォーマット戦略の転換 — 「量産ショート」から「登録が付く形」へ
競合実データは、このジャンルの登録は**低頻度・高品質**で付くことを示す。現行 `autopilot.gen_type = "short"`（テキストカード・pillow作画・1日1〜2本）は、登録者価値が最も低いSCP図鑑型に該当。

- **daily-science**: 主戦場を **10〜15分の長尺解説**へ寄せる。競合上位（665k/497k/449k）は全て長尺。ショートは「長尺への入口（フック＋“続きは本編で”）」に役割を限定し、**必ず本編動画へ内部リンク**（`short_description_template` は既にその設計 → これを台本CTAでも徹底）。
- **scp-lab**: 「長尺物語（404studio型）」か「1本の質を上げた短編」の二択に集中。テキストカードの量産は縮小。1本の作り込み（作画品質・演出）に予算を寄せる（メモリの画像品質改善2026-07と整合）。
- **投稿頻度**: 1日1〜2本の物量から、**週3〜4本の高品質**へ。同じ生成コストを“本数”ではなく“1本の深さ・作画”に再配分。

### C. 【P1】登録CTAの抜本強化（内部評価で最下位＝伸びしろ最大）
1. **説明文テンプレートに登録導線を必須化**。現 `main_intro` 末尾を
   「ぜひ最後までご視聴ください！」→「**役に立ったらチャンネル登録で応援お願いします！毎日、日常の“なぜ”を解説しています**」等、登録を明示的に求める文言へ。
2. **台本CTAの位置と回数を設計化**。`content_policy.cta_position = "after_hook"` に加え、**動画終盤（クライマックス直後の満足度ピーク）で2回目の登録CTA**を入れる（フック直後の1回だけでは弱い）。
3. **“次の1本”予告で回遊→登録**。まとめセクションに関連本編への誘導を定型化（シリーズ内回遊が登録率を押し上げる）。
4. CTA改善は `scenario_evaluations.cta_effectiveness` で効果を追跡（測定復旧後）。

### D. 【P2】テーマ選定を「登録転換」基準へ
現状のテーマ選定（`theme_priority`＝身近な体の不思議/日常の違和感）は**CTR・維持率狙いで方向性は妥当**。ただし登録至上に最適化するなら:

1. **シリーズ化＝登録の主動力**。単発の雑学より「体の不思議シリーズ Vol.○」のように**続きを見たくなる連番設計**にする。競合の登録は“この人の続きが見たい”で付く。
2. **重複テーマの徹底排除**。最新レポートで**類似ペア15件・類似度1.0の完全重複が複数**検出。同テーマ反復は「またこれか」で登録機会を毀損。既存の2段dedup（語彙＋意味）＋pop-timeゲートを厳格化し、`run_*.py` 手動スクリプト経由の重複投入（既知の氾濫原因）を止める。
3. **“伸びた系統の続編を積む”ループを、再生ではなく登録貢献で回す**（測定復旧が前提）。現行 `act` は「絶対再生30以上のバズ続編」をトリガにしているが再生が測れず0件。KPIを `subs_gained` に差し替える。
4. **反直感・問いかけ型タイトル**を継続（競合の勝ち筋と一致。現行の good_examples は良い方向）。

### E. 【P2】“登録者が増えた台本”の逆算学習ループ（資産活用）
台本は全文アーカイブ済み（§1）。測定復旧後は:
- 登録転換率 上位動画の台本を `scenario_evaluations` と突き合わせ、**「登録が付いた台本の共通構造」を抽出 → プロンプトにフィードバック**。
- 既に `model_scenario_records`（どのモデル・案が選ばれたか）と `blind_eval` があるので、**選抜基準に「登録転換率」を後付けで結合**すれば、blind_eval を“登録に効く台本を選ぶ”方向に矯正できる。
