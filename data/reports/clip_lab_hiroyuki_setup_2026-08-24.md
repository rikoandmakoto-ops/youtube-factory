## 2. 修正した実害

### 2-1. 【権利】発話は最高スコアなのに、映像が第三者のマンガだった

最初のテスト生成で選ばれた区間（`naVkgtFmRvg` 9558s〜9588s）は、
**30秒間ずっと原作マンガ『左ききのエレン』のページを画面共有しているコマ**だった。

これは公開できない。allowlist の許諾は「その配信者の配信」に対するもので、
**配信内に映っている第三者の著作物には及ばない**。切り抜き先が丸ごと他人の作品に
なると、許諾の範囲外を公開することになる。加えてショートで30秒 1枚絵が動かないのは
離脱の直行便でもある。

字幕（発話）だけで区間を選ぶ設計上、この失敗は**構造的に再発する**。

**対策: `backend/pipeline/clip_factory/visual_guard.py`（新規）**

ffmpeg だけで完結する静止画検出。64x36 グレースケールに落として毎秒2フレーム抜き、
隣接フレームの平均絶対差を見る。トーキングヘッドは黙っていても常に微動するが、
画面共有の静止画はゼロに張り付く。OpenCV も顔検出も要らない。

同一配信・同一画質の9区間での実測値:

| 区間 | 差分中央値 | 静止率(<1.0) | 判定 |
|---|---:|---:|---|
| `naVkgtFmRvg_3821_3858` | 6.93 | 0% | OK（本人が喋っている） |
| `_o8W_QKNHEo_6651_6697` | 1.90 | 31% | OK |
| `daulqJwmooE_5648_5712` | 1.86 | **41%**（良判定の最悪値） | OK |
| `naVkgtFmRvg_9554_9591` | **0.02** | **100%** | **NG（マンガ画面共有）** |

閾値は静止率 0.70 / 中央値 0.50。良判定の最悪値（41%）との間に29ポイントの余裕がある。
**判定不能なとき（ffmpeg 失敗・numpy 無し）は通す** — ゲートが壊れて全部落ちると
autopilot がその日を丸ごと落とすため、確信を持って落とせるときだけ落とす。

落とされた区間は**予備の区間に自動で差し替えて落とし直す**（`engines/local.py` の
`_materialize_checked`）。従来は上位 `count` 本だけ残して捨てていたので、静止画を
掴んだ日は素材のDLからやり直しになっていた。全滅した場合は例外を投げる
（`ok=True` で 0本を返すと autopilot が「成功したが何も出ていない」状態で静かに止まる）。

### 2-2. 【権利】ゲストの発言を「ひろゆきの切り抜き」として出していた

2本目のテスト生成で選ばれた区間は、話しているのが**ひろゆき本人ではなくゲスト
（西村ゆか）**だった。`content_policy.avoid` に
「ゲストの発言が主役の部分（ゲスト側の許諾が別途必要）」と書いてあるのに、
これを機械的に効かせる仕組みが無かった。

自動字幕には話者情報が無いので、区間だけを見て「今喋っているのが本人かゲストか」は
判定できない。タイトルは「誰が出ている回か」をチャンネル側が明示している唯一の場所
なので、**回ごと落とす**のが現実的な唯一のゲート。

**対策: allowlist に `exclude_title_patterns` を追加**（`acquisition._matched_exclude_pattern`）。
ひろゆき側に設定した除外パターン:

```
VS|ＶＳ|vs\.  /  討論|対談|対決  /  ゲスト  /  【.*(エレン|恋愛病院|語る夜).*】
と語る  /  参戦
```

権利判定（`classify`）は唯一の窓口のまま。このフィルタは **clippable を theme_only に
落とす方向にしか働かない**（theme_only を昇格させない）。
設定ミスの正規表現でも調達全体を止めないよう、`re.error` は部分一致にフォールバックする。

### 2-3. 【表示】出典と食い違う固定ハッシュタグ／タグ

全動画の説明欄に `#ひろゆき #岡田斗司夫` が固定で入っていた。ひろゆき回に
`#岡田斗司夫` が付き、その逆も起きる。検索タグ（`default_tags`）も同様に
両方の名前が全動画に入っていた。

**対策**: 固定側からは配信者名を外し、出典に依存しない語だけにした
（`#shorts #切り抜き #名場面`）。誰の切り抜きかは `description_template.short_intro` の
`{credit_name}` が動的に入れる（元動画URL・チャンネル名は従来どおり必ず入る）。

あわせて `auto_comment.question` を修正。「フル解説も出してるよ」と書いてあったが、
このチャンネルはフル解説を作っていない。

### `external.py` の weight 順ソートについて

`weight` を 5 対 1 にしただけでは**ひろゆきが選ばれなかった**（実測: weight 1 の
岡田斗司夫が選ばれた）。原因は2段構え:

1. `prepare_limit=3` で字幕を取りに行く本数を打ち切るが、プールは**再生数順**だった。
   岡田斗司夫の方が clippable が99本あるため、枠を先に埋めてしまう。
2. `pick_source` は「切り抜き済み本数が最少の動画」に絞ってから weight 抽選をする。
   未使用の動画が1本でも混ざると、**weight が効く前に主ソースが候補から消える**。

weight 順に用意することで、主ソースの在庫が尽きた日だけ下位チャンネルが出てくる
＝フォールバックとして期待どおりに振る舞うようになった。

## 6. 残課題・注意点

### 6-1. 【最重要】在庫が構造的に薄い

ひろゆき側で切り抜けるのは **3本 × 5クリップ = 15本**、うち **8本が消化済み**。
1日1本で **約1週間**しか持たない。その後は岡田斗司夫にフォールバックし続ける。

**推奨アクション（人の作業が必要）**:
`permission_source_url` に登録済みの **gcd.getnews.jp（ガジェ通クリエイターデータベース）**
に切り抜き制作者として登録し、正規の素材配布ルートを使うこと。
現状の「説明欄の文言を状況証拠として拾う」方式は在庫が薄いうえに、
`permission_note` にあるとおり**収益化可否・クレジット表記義務を書面で確認していない**。
公開運用を続けるなら、ここは埋めるべき穴。

### 6-2. 話者の判別ができない

自動字幕に話者情報が無いため、`exclude_title_patterns`（回単位）が唯一の防御。
**タイトルにゲストが現れないコラボ回はすり抜ける。** 恒久対策には話者分離
（diarization）が要るが、現環境（Python 3.9・OpenCV/Whisper 無し・Anthropic キー無し）
では割に合わない。当面はパターンの追加保守で対応する。

### 6-3. その他

- 映像ゲートは**静止画しか見ない**。動きのある第三者映像（アニメ・映画の再生）は通る。
- `視聴維持率`（retention）による区間選定は外部素材では使えない
  （Analytics は自社チャンネルしか引けない）。台本スコア＋LLM のみ。
- `NOIMOS_API_KEY` 未設定のため `clip.engine` は `local` のまま。今回の実装は
  すべて local エンジン側。
- 今回の変更は**コミットしていない**（依頼どおり）。未コミット変更が大量にあるため、
  コード（`backend/`）と実行結果（`data/`）を分けて積むこと。
