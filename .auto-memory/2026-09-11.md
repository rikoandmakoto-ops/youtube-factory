## 1. 今日いちばん効く発見 — タイトル実効文字数と登録転換

09-08 スナップショット（views>0・全12ch・n=330）を**実効文字数**（ハッシュタグと【】を除いた本文）で刻む:

| 実効字数 | 本数 | 再生 | 登録/千再生 |
|---|---:|---:|---:|
| 0-14字 | 60 | 74,419 | 0.242 |
| 15-19字 | 52 | 60,899 | 0.279 |
| 20-24字 | 63 | 62,577 | 0.400 |
| **25-29字** | 72 | 54,987 | **0.637** |
| 30字以上 | 83 | 70,479 | 0.355 |

- **25〜29字を頂点とする逆U字**。最弱帯（0-14字）の2.6倍。
- **全330本のうち112本（34%）が20字未満**だった。
- ch別の平均実効長と20字未満率は転換率の順位とよく一致する:
  company-facts 27.9字/2% (0.715) → akashic 26.5字/41% (0.570) → scp 24.5字/26% (0.791)
  … clip-kaneko 19.3字/53% (0.169) → clip-lab 18.2字/67% (0.024) → clip-fukada 16.1字/85% (0.211)
- **`title_rules.min_effective_chars_target` に自然文で書いてあった「実質20字以上」は1本も効いていなかった。**
  backend が読むのは `hard_constraints` だけ、という既知の鉄則にまた引っかかっていた。

→ **本日 `title_constraints.py` に `min_effective_chars` を実装**し、8ch の hard_constraints へ入れた（下限20・狙い25〜29）。
   機械修復はしない（文字を足すのは水増しになるので、検査と再生成 advice のみ）。

### 実装時にハマった罠（重要）

`min_effective_chars` を足した直後、**`repair()` が全chで死んだ**。
`repair()` は候補を `check()` にかけ「違反が `require_any_of` だけなら採用」という条件だったため、
語を足した候補が「まだ20字に届かない」だけで棄却され、原文を返すようになっていた。
→ `UNREPAIRABLE_RULES`（原理的に repair で直せない規則の集合）を定義し、採用条件と
既存テスト2件の判定から除外した。**下限系の制約を足すときは repair の採用条件を必ず見ること。**

## 2. 「なぜ〇〇なのか」疑問形は ch を選ぶ（09-10 の判定は誤りだった）

200再生以上・タイトルに「なぜ／のか／どうして」を含むかで分けた登録/千再生:

|---|---:|---:|---:|---|
| scp-lab | 1.324 (n=12) | 0.505 (n=25) | 2.62 | **有効** |
| daily-science | 0.534 (n=30) | 0.177 (n=6) | 3.01 | **有効** |

- scp-lab は**閾値を0/200/500に振っても 1.32 vs 0.51 で不動**、最大寄与1本を除いても 1.147。頑健。
- **09-10 の「scp-lab は疑問形が明確に負」という判定は誤りだった。** 09-11 朝の自動 run がこれを
  正しく反転させており、本日の独立再測でも run の側が正しいと確認できた。
  → **09-10 のような「ch内対照」の結論を、次の日に必ず独立再測すること。** 符号が逆になる。
- pokemon-lab は既に `forbid_prefixes: ["なぜ","何故","なんで","どうして"]` を持っており、
  09-11 朝の run も当chだけは二人称主軸へ分けていた。ch別に分ける判断は妥当。

### 付随して見つけた矛盾
yokai-watch は `hard_constraints.forbid_patterns` に「末尾の疑問符」禁止を持つのに、
09-11 朝の run が「なぜ〇〇なのか」を最優先にした。疑問符付きで書くと**必ずゲートに落ちて再生成に回る**。
→ 4ch に「疑問形は体言止めで書き、末尾に？を付けない」注記を追加。
   **疑問形の効果は語順（なぜ〜のか）にあり、疑問符の有無ではない。**
