### 🔴 `title_constraints.repair()` をキューに当ててはいけない（本日実測）

57件に当てたら**ほぼ全てで日本語が壊れた**。repair は
- `max_chars` 違反 → **末尾切り落とし**
- `forbid_digits` 違反 → **数字の削除**
で通そうとするため：

| 元 | repair 後 |
|---|---|
| …愛らしい外見が起こした財団史上最恐の収容違反 | …愛らしい外見が**起こしの真相**（文法破壊） |
| …が[DATA EXPUNGED]した恐ろしい記録 | …が**[DATA EXP**（トークン途中切り） |
| シェイミの2形態を分ける気温**5度**の正体 | シェイミの2形態を分ける**気温正体**（事実欠落＋文法破壊） |
| ぬらりひょんの正体、江戸期**4図**で姿が変わった | …**江戸期図**で…（事実欠落） |
| 海底に沈んだ都市の入口 — …石造構造物は何を語るのか | …**何を語の正体**（文法破壊） |

**違反数は確かに減る。だから「合格」として通ってしまう。検査より悪い。**
→ **長さ・数字の違反は LLM 再生成に回す。** 機械修復してよいのは**絵文字除去だけ**（意味を一切変えない）。
→ この判断を `test_fixes_20260912_orch.py::TestRepairIsNotUsedOnQueueTitles` で固定した。repair の挙動が変わったらテストが落ちるので、そのとき**測り直す**こと。

※ モジュールの docstring は `min_effective_chars` について「機械修復はしない」と明記していたが、**`max_chars` と `forbid_digits` の repair は元から有効**だった。「repair は安全」と一般化しないこと。
