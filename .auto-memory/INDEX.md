## 常設の学び（更新型）

### 判断指標
- **唯一の改善指標は「登録/1000再生」**（2026-09-04 決定）。再生数・維持率が改善しても本数値が動かない施策は不採用。
- **維持率は判断に使わない**。chごとに登録転換との符号が逆（yokai 3.00倍 / scp 0.95倍）。参考値。
- **いいね率は先行指標として使える**。高評価率4分位と登録転換の単調関係が5回連続で再現（09-10 時点）。維持率と違い符号が反転しない。

### タイトル
- **答え提示語（理由/正体/本当の/実は/わけ/なぜ/真相/裏側/実態）を必ず1語入れる** — 登録/千 0.57 vs 0.31（1.84倍・n=196）。ただし本編で必ずその答えを言い切ること。「疑問を投げて答えを渡さない」構造が不合格の本体。
- **「秘密」は禁止** — 登録/千 0.120（n=18）。09-09 に全6chの `banned_words` へ登録済み。
- **「99%が知らない」型は禁止** — 登録/千 0.194（n=11）vs 0.510。09-09 に `forbid_patterns` へ正規表現で登録済み。
- **連番プレフィックス（#NN：）とシリーズ接頭辞は禁止** — 0.84倍で負。09-11 に fake-paper の「架空論文ファイル」も禁止（接頭辞に9文字取られて本文が残らず、17本で登録0だった）。
- **実効文字数は 25〜29字が頂点の逆U字**（2026-09-11・n=330）。0-14字 0.104 / 15-19字 0.279 / 20-24字 0.402 / **25-29字 0.646** / 30-34字 0.389 / 35字以上 0.345。4分位でも同形（Q1 9-21字 0.227 / Q2 0.476 / Q3 27-35字 0.518 / Q4 35-54字 0.352）。20字未満は 66/330本（20%）。下限20字は 09-11 に `hard_constraints.min_effective_chars` として8chへ実装済み（`min_effective_chars_target` の自然文は backend が読まないので効いていなかった）。実効長＝ハッシュタグと【】を除いた本文で、**判定は `title_constraints.effective_len()` に一本化**（レポート側に別実装を持つと基準がずれる）。ch平均で見ると相関は弱いので、**本数レベルの分布で見ること**。
- 全角30字以内・絵文字なし。
- **「なぜ〇〇なのか」疑問形はchを選ぶ**（2026-09-11 実測）。有効: scp-lab 2.62倍 / daily-science 3.01倍 / yokai-watch 1.84倍 / 2ch-matome 1.37倍。**逆効果: pokemon-lab 0.19倍**。判断不能: company-facts（n=1）。**末尾に「？」は付けない**（効いているのは語順。yokai-watch は末尾疑問符を hard_constraints で禁止しているため、付けると必ずゲートに落ちる）。
- **チャンネル横断で同じ答え提示語に寄せない**。6ch×3枠を9語で分け合うため、全chが「正体」に寄ると横断ゲートが毎日発動する（09-07 は114回発動）。ch別に主軸語を割り当てる。

### 構造
- **冒頭3秒が全て**。離脱の崖は全12chで再生位置5%→10%（≒1.5〜3秒）に集中。
- **company-facts だけ崖が浅い（-1.7pt、他は-3.0〜-8.4pt）**。差は「冒頭で具体的な数字を画面最大サイズで出す」ことと「画像がファクトごとに切り替わる（max_images=6）」の2点。全chへ移植済み。
- 挿絵は均等配置ではなく、離脱が集中する 5%・10%・20%・40% 地点の直前に置く。

### ゲートの配線（2026-09-12 判明）
- **`hard_constraints` は `title_rules` の**下**にある**（`d["title_rules"]["hard_constraints"]`）。トップレベルで探すと全chが「未設定」に見え、**存在するゲートを消しにかかる事故**になる。09-12 に一度踏みかけた。
- **`title_constraints` に channel を渡すときは `channel._raw`**。`ChannelProfile` 自体や `.data` を渡すと `is_enforced()` が常に False になり、**検査が静かに無効化**される。`generator._enforce_title_constraints` と同じ経路を使うこと。
- **キュー補充（`theme_queue.replenish`）は 09-12 まで `title_constraints` を一度も通していなかった**。各chが自分で設定したゲートに自分のキューが落ちる状態で、**未公開99件中 合格は24件（24.2%）**。company-facts は**自ch の `banned_words` にある絵文字を先頭に付けて12件全滅**していた。09-12 に `_annotate_title_gate()` を追加。
- **キューでは弾かず「印を付ける」**（`title_gate_ok`）。弾くと 09-11 の「キュー全件ブロック」を再発させる。
- ⚠️ **`title_constraints.repair()` をキューのタイトルに当ててはいけない**（2026-09-12 実測・57件）。`max_chars` 違反は**末尾切り落とし**、`forbid_digits` 違反は**数字の削除**で通そうとするため日本語が壊れる（「…外見が起こした財団史上最恐の収容違反」→「…外見が起こしの真相」／「…が[DATA EXPUNGED]した恐ろしい記録」→「…が[DATA EXP」／「気温5度の正体」→「気温正体」）。**違反数は減るので「合格」として通ってしまい、検査より悪い。** 長さ・数字の違反は LLM 再生成に回す。機械修復してよいのは**絵文字除去だけ**（意味を変えないため）。docstring の「機械修復はしない」は `min_effective_chars` の話で、`max_chars` / `forbid_digits` の repair は元から有効。**「repair は安全」と一般化しないこと。** 判断は `test_fixes_20260912_orch.py` で固定済み。
- **切り抜き系のゲートは禁止系のみ**。`min_effective_chars` と `require_any_of` は入れない（タイトルが発言の引用なので誤引用を作る）。09-12 に clip-lab / clip-fukada / clip-kaneko へ付与し、この制約自体も回帰テストで固定した。
