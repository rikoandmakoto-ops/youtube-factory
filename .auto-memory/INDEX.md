## 常設の学び（更新型）

### 時刻とデータの読み方（2026-09-14 追加）
- **`video_metrics.published_at` は UTC。** JST で日別の公開本数を数えるときは必ず +9h してから日付を切る。UTC のまま数えると「09-13 23:15 公開」が実際は「09-14 08:15 公開」になり、日をまたいで1本ずれる。
- **Analytics の反映ラグは約2日。** 公開翌日に `views=0` は障害ではない（09-14 時点で 09-09公開は 3,277再生・09-13公開は0）。**「1日経っても0だから公開失敗」と読むと誤診する。**
- **`oauth_tokens.updated_at` は最終リフレッシュ日であって付与日ではない。** 残寿命を `updated_at + 7日` で計算すると毎晩リセットされて見え、**失効を見落とす**。7日の壁は付与時点から動く。
- **`repair()` に無い規則は `check()` にあっても素通りする。** `hard_constraints` に規則を足すときは `repair()` 側の除去処理を必ず確認する。`UNREPAIRABLE_RULES`（`max_digit_groups` / `require_any_of` / `min_effective_chars` 等）は設計上 `ok:false` のまま公開へ進む。
- **config は誰も触っていなくても動く。** company-facts の top-level `days_of_week` が 09-13→09-14 で `[3,4,5]`→`[1,4,5]` に変わっていた。**「前回こうだったはず」で書かず、毎回実ファイルを読むこと。**

### 集計の作法（2026-09-13 追加・最優先）
- **タイトル要素・曜日・時間帯の効果は必ず ch 内で見る。** ch横断のクロス集計は、要素の使用率が ch ごとに偏っている限り、**ch の実力差を要素の効果として誤読する**（シンプソンのパラドックス）。実例2件: ①絵文字先頭 — 横断 0.590(n=21) vs 0.353(n=276) で「強い」に見えるが、21本のほぼ全部が company-facts。ch内では 0.686 vs **0.915** で逆転＝むしろマイナス。②曜日 — scp-lab 単独では土0.763・日0.774 だが、ゆっくり6chプールでは土0.268（下から2番目）。③維持率バンド（2026-09-15 追加） — 全13chでは >=70% が 0.258 で最下位に見えるが、**当該帯の総再生の61.6%が切り抜き2ch（clip-lab 34.4% / clip-fukada 23.6%）**。ゆっくり7chに限ると 0.514 で最下位ではなく、真の最下位は <30% の 0.245。
- **系統（ゆっくり / 切り抜き / 長尺）をまたいだプール集計は、維持率・CTR・平均再生では必ず交絡する（2026-09-15 追加）。** 制作方式が指標の分布そのものを決めるため（切り抜きは元動画をそのまま出すので維持率が構造的に70-90%に張り付く）、「指標の効果」ではなく「系統の実力差」を測ってしまう。**ch 内対照のルールは系統単位にも適用する。**
- **倍率を引用するときは窓と ch 構成を必ず併記し、分子と分母で同じ分類を使う。**（ゆっくり÷切り抜き: 09-12 4.58倍/切り抜き3ch・09-13 4.56倍/4ch・09-14 4.81倍・**09-15 4.72倍（ゆっくり8ch 0.526 ÷ 切り抜き4ch 0.111）**。**6日連続で数え違いが発生している。単独では意味のない数字**）
- **系統は3分類。`akashic-librarian` は「長尺系（chatcut）」で、切り抜き系ではない（2026-09-15 追加）。** 09-15 に akashic を切り抜きへ混ぜて分子7ch÷分母6chで数え、倍率を 3.89倍と誤記した（正: 4.72倍）。**ゆっくり8ch = daily-science / scp-lab / yokai-watch / company-facts / 2ch-matome / pokemon-lab / fake-paper / socio-rx、切り抜き4ch = clip-lab / clip-fukada / clip-kaneko / clip-animal、長尺1ch = akashic-librarian。**
- 🆕 **プール集計で「単調」「n回連続で再現」と言う前に、必ず ch 内対照を1回通す（2026-09-16 追加・最優先）。** いいね率は「6回連続で単調」と記録していたが、**判断指標そのものに ch 内対照を適用したのは 09-16 が初めて**で、そこでは 3/5ch だった。09-13 に決めた「効果は ch 内で見る」を、タイトル要素・曜日・時間帯には適用していたのに、**判断指標には適用し忘れていた。ルールの適用漏れは、ルールを作った本人がいちばん気づかない。**
- 🆕 **連続するスナップショットを「独立な再現」と数えてはいけない（2026-09-16 追加）。** 直近50本の窓は1日で 0〜4本しか入れ替わらないため、隣接スナップショットは**同一動画が約95%重なる**。「3スナップショット連続で 5/5ch」は**実質1回の観測**。独立性を確保するなら **5日以上離すか、公開コホートで切る**こと。
- 🆕 **`video_metrics` の `views` / `subscribers_gained` は直近30日窓（2026-09-16 確定）。** `youtube_analytics.fetch_video_metrics(days=30)`。生涯累計ではないので**同一動画でも日をまたいで減る**（09-15 の 2ch-matome は同一50本で -2,618）。09-15 の「固定本数窓なので入れ替わる」とは**別の効果**で、両方が同時に総再生を押し下げる。**総再生の前日比は二重の意味で指標にならない。**
- 🆕 **ログからの集計は「イベント行を特定してから」数える（2026-09-16 夜 追加）。** `video_id` は1本につきログの複数箇所（series_links / auto_comment / upload_done / thumbnail retry）に出るため、**`rfind` した位置の近傍文字列で成否を判定すると結果が丸ごと反転する**（本日サムネ403を「14本中0本」と出した。正しくは `upload_done` 行に限定して **10本**）。**近傍検索は集計の代用にならない。**
- **`orch_config_changes_*.json` の `queue_before` は「script が読んだ瞬間の値」であって「その日の始値」ではない（2026-09-15 追加）。** autopilot が並行してキューを消費するため、git HEAD の値と1〜2件ずれる。前日比の分母に使うな。

### 判断指標
- **唯一の改善指標は「登録/1000再生」**（2026-09-04 決定）。再生数・維持率が改善しても本数値が動かない施策は不採用。
- **再生数と登録/千は弱い負の相関（r=-0.140・n=205・2026-09-13）。再生の最大化は目的関数ではない。** 実例: clip-lab 223,866再生で登録1、clip-fukada は有効CTR 6.24%（全ch1位）で登録/千 0.193。
- **登録を説明する指標は高評価率だけ**（2026-09-13 に n=205 で独立再現）。高評価率 r=+0.308 / CTR r=+0.069 / 維持率 r=-0.047。

### ゲートの配線（2026-09-12 判明）
- **`hard_constraints` は `title_rules` の**下**にある**（`d["title_rules"]["hard_constraints"]`）。トップレベルで探すと全chが「未設定」に見え、**存在するゲートを消しにかかる事故**になる。09-12 に一度踏みかけた。
- **`title_constraints` に channel を渡すときは `channel._raw`**。`ChannelProfile` 自体や `.data` を渡すと `is_enforced()` が常に False になり、**検査が静かに無効化**される。`generator._enforce_title_constraints` と同じ経路を使うこと。
- **キュー補充（`theme_queue.replenish`）は 09-12 まで `title_constraints` を一度も通していなかった**。各chが自分で設定したゲートに自分のキューが落ちる状態で、**未公開99件中 合格は24件（24.2%）**。company-facts は**自ch の `banned_words` にある絵文字を先頭に付けて12件全滅**していた。09-12 に `_annotate_title_gate()` を追加。
- **キューでは弾かず「印を付ける」**（`title_gate_ok`）。弾くと 09-11 の「キュー全件ブロック」を再発させる。
- ⚠️ **`title_constraints.repair()` をキューのタイトルに当ててはいけない**（2026-09-12 実測・57件）。`max_chars` 違反は**末尾切り落とし**、`forbid_digits` 違反は**数字の削除**で通そうとするため日本語が壊れる（「…外見が起こした財団史上最恐の収容違反」→「…外見が起こしの真相」／「…が[DATA EXPUNGED]した恐ろしい記録」→「…が[DATA EXP」／「気温5度の正体」→「気温正体」）。**違反数は減るので「合格」として通ってしまい、検査より悪い。** 長さ・数字の違反は LLM 再生成に回す。機械修復してよいのは**絵文字除去だけ**（意味を変えないため）。docstring の「機械修復はしない」は `min_effective_chars` の話で、`max_chars` / `forbid_digits` の repair は元から有効。**「repair は安全」と一般化しないこと。** 判断は `test_fixes_20260912_orch.py` で固定済み。
- **切り抜き系のゲートは禁止系のみ**。`min_effective_chars` と `require_any_of` は入れない（タイトルが発言の引用なので誤引用を作る）。09-12 に clip-lab / clip-fukada / clip-kaneko へ付与し、この制約自体も回帰テストで固定した。
